Lab 4: Pointers, Aliasing, and In-place Reversal

In this lab, you will investigate how pointers refer to objects, test a swap function that appears to work, and build a function that reverses part of an array in place. Your explanations and test cases matter as much as your final output.

1. Objectives and Lab Workflow

  • Distinguish a pointer variable from the object it points to.
  • Explain aliasing: two or more pointers referring to the same object.
  • Use pointer parameters to modify the caller’s data.
  • Pass an array segment to a function using a starting address and a length.
  • Distinguish address equality, equal contents, and permission to modify data.

Use C throughout. This lab does not require dynamic memory allocation, file input, arrays of pointers, or pointers to pointers. For each investigation, predict first, run or debug second, and explain any difference. Keep your original predictions in your notes.

Working with addresses: The lecture uses a 32-bit model for address exercises. Your actual environment may use a different pointer size. Measure it with sizeof; do not assume that every machine uses four-byte pointers. Print object-pointer addresses with %p and a conversion to void *, for example:

printf("p = %p, sizeof p = %zu\n", (void *)p, sizeof(p));

Exact address values can differ between runs. Focus on which object an address identifies.

3. Investigation B: Does This Swap Always Work?

The following function uses arithmetic to exchange two integers. Treat it as code under review, not as a trusted helper.

void swap_arithmetic(int *a, int *b)
{
    *a = *a + *b;
    *b = *a - *b;
    *a = *a - *b;
}

3.1 Construct Counterexamples

Start each case with freshly initialized variables. Predict the result before testing.

CaseInitial state and callQuestion
Different valuesx = 3; y = 8;
swap_arithmetic(&x, &y);		Does the usual case work?
Equal values, different objectsx = 5; y = 5;
swap_arithmetic(&x, &y);		Does equal content cause a problem?
The same object twicex = 5;
swap_arithmetic(&x, &x);		What changes when both pointers identify one object?
Large valuesx = INT_MAX; y = 1;
swap_arithmetic(&x, &y);		Can every intermediate result be represented as an int?

For the third case, step through each assignment and record the value of x. For the fourth case, include <limits.h> and reason about the range before execution. Signed integer overflow is undefined behavior in C: there is no required numerical result. A value observed in one run is not a guarantee, and running the overflowing case is not required.

3.2 Repair the Function

Implement:

void swap_int(int *a, int *b);

Both arguments must point to valid, writable int objects. Your function must exchange their values when the addresses differ and preserve the value when both arguments point to the same object. Use a temporary integer; do not rely on arithmetic swapping.

Now inspect this second attempted solution:

void swap_attempt(int *a, int *b)
{
    int *temp = a;
    a = b;
    b = temp;
}

Discuss: Does this function exchange the caller’s integers? Which objects do its assignments actually modify? Explain why C’s pass-by-value rule still applies when parameters are pointers.

Checkpoint: Show a failing test for swap_arithmetic() and the corresponding successful test for swap_int(). Explain the difference between equal values and equal addresses.

4. Main Task: Reverse Part of an Array

Implement a reusable function that reverses a contiguous segment in place:

void reverse_segment(int *first, int count);

first identifies the beginning of the segment, and count is its number of elements. The function does not receive the original array’s total length or the segment’s starting index.

4.1 Function Contract

  • count is nonnegative. For a nonempty segment, the caller provides a valid range of count writable integers.
  • For this lab, an empty segment may start at any element or at the position just past the end of the array. Do not dereference that position. Null-pointer handling is not required.
  • For count equal to 0 or 1, leave the data unchanged.
  • Use your repaired swap_int(). Do not allocate a second array.
  • Do not modify any element outside the selected segment.

You may control the loop using integer positions and construct addresses for the swap calls. A two-pointer implementation is an optional alternative. Handle an empty segment before constructing a pointer to its last element: first + count - 1 is not a valid general way to initialize an empty range.

4.2 Input and Expected Behavior

Use a fixed capacity of 20 integers. Read n, then n array elements, then a zero-based starting index and a count. For example:

7

2 3

Expected output:

Before: 10 20 30 40 50 60 70
After:  10 20 50 40 30 60 70

The call for this example is reverse_segment(a + 2, 3). The two elements before the segment and the two after it must remain unchanged.

5. Investigation C: Equal Contents, Equal Addresses, and const

Use this setup:

char s1[] = "cat";
char s2[] = "cat";

char *p = s1;
const char *q = s1;
char *const r = s1;

Predict and test s1 == s2 and p == q. These expressions compare addresses, not string contents. Then modify the first character through p and observe what you read through q.

Treat each statement below as an independent case, starting from the original setup. Predict whether it is allowed, and identify whether it would change an address or a character. Compile one case at a time, recording any diagnostic; do not cast away const.

Finally, compare the following pointers:

const char *u = "cat";
const char *v = "cat";

printf("%d\n", u == v);

Record the result, but do not treat it as a universal answer. Identical string literals may share storage or occupy different storage. Use content comparison, such as strcmp() from <string.h>, when you need to compare strings. Do not attempt to modify a string literal: that has undefined behavior, not a guaranteed runtime error.

6. Optional Extension: Mirror Two Rows

Use a small two-dimensional array:

int image[2][3] = {
    {11, 12, 13},
    {21, 22, 23}
};

Predict how far image + 1 advances compared with image[0] + 1. Print their addresses using %p and (void *), and relate the results to the types of the pointed-to objects. Use %d when printing an integer element.

Then reuse your function:

reverse_segment(image[0], 3);
reverse_segment(image[1], 3);

The expected rows are 13 12 11 and 23 22 21. Explain why you can reuse a one-dimensional segment operation on each row. Keep each reversal within its row; a two-dimensional array is not an int **.
